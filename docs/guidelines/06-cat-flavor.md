# 猫要素の使いどころ

設計書 §10.6 のルールです。5 項目あります。猫要素は「どこにでも出す」ものではなく、出す場所を決めて使います。

## 1. 常に出てよいのは耳付きアイコンだけ

Icon は猫耳付きで描かれます。これは常に出てかまいません。逆に言うと、それ以外の猫要素は場所を限ります。

## 2. マスコットは 4 か所だけ

Mascot を出してよいのは次の 4 か所だけです。

- 空状態（EmptyState）
- 初回ローディング
- 404
- ログイン

一覧の上、フォームの脇、ダッシュボードの余白などには置きません。EmptyState は現在のテーマのマスコットを自分で描くので、利用側で Mascot を足す必要はありません。

```tsx
<EmptyState
  title="まだ案件がありません"
  description="最初の案件を追加すると、ここに一覧が表示されます。"
  action={<Button>案件を追加する</Button>}
/>
```

## 3. 猫の顔のシルエットは 2 か所だけ

猫の顔のシルエット（`cat_face`）を使うのは、Checkbox のチェックマークと Avatar のフォールバック（画像が無いとき）だけです（設計書 D13）。Badge は通常の丸（ピル）で、猫要素はありません。他の部品のチェックやアイコンを猫の顔に差し替えないでください。

## 4. 業務データ領域に猫を入れない

業務データを表示する領域（Table・Form・詳細）に、猫のイラスト・絵文字・装飾を入れません。文言についても同じで、猫の言葉遊びは空状態とローディングの文言だけに限ります（[04-writing.md](./04-writing.md)）。

## 5. NekoThemePicker はヘッダー右上

テーマ切替 UI（NekoThemePicker）はヘッダー右上に置きます。被験者が触っても壊れないようにします。テーマの指定は `<html data-neko-theme="…">` と NekoThemeProvider の `defaultTheme` でだけ行います。

実例: `src/app/site-header.tsx`

## 6. 「かわいいけど使いにくい」は目的達成

「かわいいけど使いにくい」と言われたら、それはプロトタイプの目的（使いにくさの指摘）が達成された状態です。猫要素を減らして対処しません。

## 早見表

| 猫要素 | 出してよい場所 |
|---|---|
| 耳付きアイコン（Icon） | 常に可 |
| マスコット（Mascot） | EmptyState / 初回ローディング / 404 / ログイン |
| 猫の顔のシルエット（`cat_face`） | Checkbox のチェックマーク / Avatar のフォールバック |
| 猫のイラスト・絵文字・装飾 | 業務データ領域（Table・Form・詳細）には入れない |
| 猫の言葉遊び | 空状態・ローディングの文言だけ |

## AI 向けの要約

- 常に出してよい猫要素は耳付きアイコン（Icon）だけ。
- Mascot は EmptyState・初回ローディング・404・ログインの 4 か所だけに出す。
- 猫の顔のシルエット（`cat_face`）は Checkbox のチェックマークと Avatar のフォールバックだけに使う。Badge は通常の丸にする。
- 業務データを表示する領域（Table・Form・詳細）に猫のイラスト・絵文字・装飾を入れない。
- 猫の言葉遊びは空状態とローディングの文言だけに限る。
- NekoThemePicker はヘッダー右上に置き、触っても壊れないようにする。
- 「かわいいけど使いにくい」は目的が達成された状態なので、猫要素を減らして対処しない。
