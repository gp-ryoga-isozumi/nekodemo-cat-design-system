# 文言

設計書 §10.4 のルールです。6 項目あります。

## 1. 文体は「です・ます」、ボタンは「〜する」

UI テキストは「です・ます」で書きます。ボタンは「〜する」の形にします。

- 良い例: 「保存する」「削除する」「追加する」「条件をクリアする」
- 悪い例: 「保存」「OK」「はい」「Submit」

## 2. エラー文は「何が起きたか」＋「どうすればよいか」

エラー文には、起きたことと次にすることの両方を書きます。

- 良い例: 「メールアドレスの形式が正しくありません。@ を含めて入力してください」
- 良い例: 「案件を読み込めませんでした。通信状況を確認して、再試行してください」
- 悪い例: 「入力エラー」「エラーが発生しました」

## 3. 見出しは名詞

見出しは名詞で書きます。

- 良い例: 「案件一覧」「基本情報」「通知設定」
- 悪い例: 「案件を一覧する」「基本情報について」

## 4. プレースホルダーに必須情報を書かない

必須情報はラベルと補足（FormDescription）に書きます。プレースホルダーは入力すると消えるため、そこにしか無い情報は読めなくなります。

- 良い例: ラベル「メールアドレス」／補足「社内で使っているアドレスを入力してください」／プレースホルダー「taro@example.com」
- 悪い例: プレースホルダー「社内アドレスのみ（必須）」だけ

## 5. 数値・日付・時刻・単位

| 種類 | 書き方 | 例 |
|---|---|---|
| 数値 | 3 桁区切り | `1,200` |
| 日付 | `YYYY/MM/DD` | `2026/09/21` |
| 時刻 | `HH:mm` | `13:05` |
| 単位 | 半角スペースなしで付ける | `120件` |

## 6. 猫の言葉遊びは空状態とローディングだけ

猫に関する言葉遊びは、空状態とローディングの文言だけに限ります（例: 「まだ何もいません」）。業務文言には入れません。エラー文・フォームのラベル・表の見出し・確認 Dialog の文言は、猫抜きの普通の業務日本語で書きます。詳しくは [06-cat-flavor.md](./06-cat-flavor.md) を参照してください。

- 良い例（EmptyState）: 「まだ案件がありません」「条件に合う案件がありません」
- 悪い例（フォームのエラー）: 「にゃんと、入力が足りないようです」

## AI 向けの要約

- UI テキストは「です・ます」、ボタンは「〜する」（保存する／削除する／追加する）にする。
- エラー文には「何が起きたか」と「どうすればよいか」の両方を書く（例: 「メールアドレスの形式が正しくありません。@ を含めて入力してください」）。
- 見出しは名詞にする（「案件一覧」「基本情報」）。
- 必須情報をプレースホルダーに書かない。ラベルと補足に書く。
- 数値は 3 桁区切り、日付は `2026/09/21`、時刻は `13:05`、単位は半角スペースなしで付ける（`120件`）。
- 猫の言葉遊びは空状態とローディングの文言だけに限る。業務文言には入れない。
