# 操作の原則

設計書 §10.3 のルールです。6 項目あります。

## 1. 主アクションは 1 画面 1 つ

1 画面の主アクション（primary ボタン）は **1 つ**です。他は secondary / outline / ghost にします。「保存する」と「複製する」を並べたくなったら、片方を secondary に下げるか Menu に入れます。

```tsx
<Button>案件を追加する</Button>
<Button variant="secondary">CSV を書き出す</Button>
<Button variant="ghost">条件をクリアする</Button>
```

## 2. 取り消し不可の操作は Dialog で確認する

削除だけでなく、**公開する・送信する・権限を変更する・一括で削除する**も「押したら戻せない」操作です。これらは Dialog（確認）を挟み、確認ボタンは `negative` にします。ボタン文言は「削除する」のように動作を書きます（「OK」「はい」は禁止）。`DialogDescription` には、一緒に消えるもの・取り消せないこと・影響する件数を書きます。

```tsx
<DialogFooter>
  <DialogCancel>キャンセル</DialogCancel>
  <DialogAction variant="negative">削除する</DialogAction>
</DialogFooter>
```

確認の強さは次の 3 段階で選びます。

| 操作 | 確認のしかた |
|---|---|
| 元に戻せる（アーカイブ、非表示、1 件の削除で復元できる） | 確認 Dialog を出さず、実行して `toast.success` の `action` に「取り消す」を置く |
| 元に戻せない（削除、公開、送信、権限変更） | Dialog で確認し、確定は `DialogAction variant="negative"` |
| 元に戻せず、対象が複数（一括削除、一括の権限変更） | Dialog で確認し、本文と確定ボタンの両方に件数を入れる（「3 件の案件を削除する」） |

- 良い例: 「この案件を削除しますか？」＋「関連する 8 件のタスクも削除されます。この操作は取り消せません。」＋「削除する」
- 悪い例: 一覧で選んだ 3 件を、確認なしで削除する

取り消せる操作の Toast の作り方は [11-notifications.md](./11-notifications.md)、一括操作の確認と結果の伝え方は [12-list-and-filters.md](./12-list-and-filters.md)、フォームの送信前後の扱いは [10-forms.md](./10-forms.md) を参照してください。

## 3. 送信ボタンの初期状態

送信ボタンは初期状態から有効にしておき、押したときに検証してエラーを項目のそばに表示します（Form の `FormMessage`）。必須項目が未入力なだけで無効化しません。無効なボタンは「なぜ押せないか」が伝わらず、キーボードやスクリーンリーダーでも到達できないためです。

- 良い例: 「保存する」は常に押せる → 押すと未入力の項目に「案件名を入力してください」が出て、最初のエラー項目にフォーカスが移る
- 悪い例: 全項目が埋まるまで「保存する」を `disabled` にし、理由を示さない
- 例外: 送信中は `loading` で二重送信を防ぐ。取り消し不可の操作で「同意」のチェックが条件になる場合は、チェックのそばに理由を書いたうえで無効化してよい

## 4. 保存後は画面を移す

保存後は編集画面に留まらず、詳細または一覧に戻して Toast で結果を伝えます。Toast は遷移先で表示します（[02-states.md](./02-states.md)）。

- 良い例: 「保存する」→ 詳細に遷移 → 遷移先で `toast.success("案件を保存しました")`
- 悪い例: 編集画面に留まったまま Toast だけ出し、利用者が次に何をすればよいか分からない状態にする

## 5. 一覧の行の操作

一覧の行クリックは詳細へ遷移します。行内の操作ボタンは行末に置きます。行全体がリンクとして働くので、行末のボタンはクリックが行のリンクに伝わらないようにします。

## 6. モーダルは短い入力だけ

モーダルは「その場で完結する短い入力」だけに使います。3 項目を超えるフォーム、途中で他の画面を参照したくなる入力、後から見直す前提の入力はページにします。モーダルは背後の画面を操作できなくするため、参照しながらの入力には向きません。

nekodemo では確認に Dialog、その場で完結する短い入力に Modal を使います。

## 実例

- 確認 Dialog と行内操作: `src/app/samples/list/page.tsx`
- Menu からの削除と Drawer: `src/app/samples/detail/page.tsx`
- 保存後の遷移と Toast: `src/app/samples/form/page.tsx`

## AI 向けの要約

- 1 画面の primary ボタンは 1 つだけにする。他は secondary / outline / ghost を使う。
- 削除・公開・送信・権限変更・一括削除など取り消し不可の操作は Dialog で確認し、確認ボタンは negative、文言は「削除する」にする。「OK」「はい」は使わない。
- 元に戻せる操作は Dialog をやめて、実行後に Toast の `action`「取り消す」で戻せるようにしてよい。対象が複数のときは本文と確定ボタンに件数を入れる。
- 送信ボタンは初期状態から有効にし、押したときに検証してエラーを項目のそばに出す。必須項目の未入力だけを理由に `disabled` にしない。送信中は `loading` にする。
- 保存後は編集画面に留まらず、詳細または一覧に戻して遷移先で Toast を出す。
- 一覧の行クリックは詳細へ遷移させ、行内の操作ボタンは行末に置く。
- モーダルはその場で完結する短い入力だけに使う。3 項目を超えるフォームや、他の画面を参照しながらの入力はページにする。
